# Generated project architecture

## Purpose

These documents are the canonical architecture contract for applications generated by Project Base Generator. A generated application receives a complete, versioned copy of this directory and does not require a link to the generator repository.

The contract applies to both supported frameworks unless a document labels a rule as Next.js-specific or React-specific. Optional features are identified explicitly. Do not infer new rules from example trees: a directory is created only when a generated file needs that scope.

## Reading guide

- Start with `project-structure.md` for scope boundaries.
- Read `coding-standards.md` and `naming-conventions.md` for code-wide rules.
- Read the relevant topic document for components, modules, core, state, API, hooks, providers, i18n, testing, Git, or tooling.
- Follow the document's **Decision Status** when a topic is deliberately extensible.

## Decision Status

- **Approved** means a project decision is part of the current contract.
- **Extensible** means the contract intentionally leaves implementation details open; additions must preserve the approved rules and must not be treated as already selected dependencies or behavior.
- Framework-specific and optional-feature rules are stated where they apply.
